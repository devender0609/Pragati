# Pragati v0.49 — Functional stabilization report

Written 2026-08-13. No Git repository was present in the supplied
archive, so there is no commit hash to cite.

This iteration was verification-first: every issue in the brief was
checked against the actual v0.48 code before anything was changed.
Three of the reported defects were real and are fixed; four were
already correctly solved in v0.48 and were left alone.

## 3. What changed

### §1 Lessons stay inside the shell
New `StudentRouteOutlet` renders the whole journey — Home → Learn →
Chapter → Lesson → Practice → Check → Results — inside one
`StudentShell`. It preserves active chapter, active concept, active
tab, back behaviour, and return destination. The lesson's back link
was hard-coded to "← Fractions Module"; it now returns to whichever
chapter opened it.

### §2 Navigation during active sessions
Tabs are now genuinely `disabled` (with `aria-disabled`) during an
assessment, not merely styled as inert. An explicit **Save & Exit**
replaces the desktop nav, a status banner explains the restriction,
and leaving with an unanswered question on screen raises a
confirmation. Answers already submitted are saved. Navigation is
restored the moment the session ends — results screens are *not*
locked.

### §3 Executable blueprints (the core fix)
New pure `chapterSessionBuilder.ts`. The blueprint fields now drive
selection:

- **Mixed practice** — `mixedPracticeItemCount` (5), hints available.
- **Chapter check** — `targetItemCount` (10), round-robin across every
  `requiredSkillId` so no skill is oversampled while another is
  starved, **no hint control rendered at all**.

Sessions record `sessionPurpose`, `chapterBlueprintId`,
`chapterBlueprintVersion`, `sampledSkillIds` (measured from the pool,
not copied from intent), `chapterId`, and `chapterModuleId` — all
optional, so every legacy session loads unchanged.

### §4 Practice actions match labels
Four distinct actions, four distinct handlers: *Practise a concept*
(one skill), *Open chapter*, *Mixed practice* (starts directly),
*Chapter check* (starts directly; rendered only where a blueprint
exists). Chapter pages no longer substitute mixed practice under the
"Chapter check" label — they say the check is not ready.

### §5 Isolation gaps closed
`ChapterLandingPage` and `LearnView` now take an optional `studentId`
and scope their progress to it. The teacher preview deliberately keeps
device-wide data.

### §8 Classroom-aware insights
New pure `teacherInsights.ts`. Membership resolves via the session's
recorded `classroomId` **or** the classroom roster — so existing
stored sessions land in the right class with **no data migration**.
With no classroom selected the heading reads "All local data", never
"class".

### §9 Teacher resource page
New `TeacherResourceOutlet`, rendered inside TeacherShell. Reports
measured counts: skills, questions, hand-authored vs generated
lessons, worked examples, misconceptions, printables, chapter-check
availability, and verification status. Every skill is listed, not just
the first.

### §12 App.tsx reduction
**2,448 → 1,306 lines.** Extracted into four coherent files rather
than one dumping ground: `Class6MathDashboard` (231),
`ModuleDashboard` (341), `TeacherStudentList` (307),
`TeacherStudentDetail` (555).

### §14 Student copy
Results split by `audience`; the measurement disclaimer stays in full
for teachers and becomes an "About this result" disclosure for
students. Removed "prototype estimate" and the "Teacher view for…"
button from student screens. Header subtitle no longer reads "Growth
assessment prototype". **Authoring metadata — seed difficulty, raw
skill code, cognitive-demand tag — is now hidden during student
sessions and retained in the teacher preview.**

## 5. Compatibility and migration impact

- **No migration required.** Every new `Session` field is optional;
  legacy records load unchanged.
- No SkillId, ModuleId, Grade, or SkillMode removed or renamed.
- `Session.skillId` (legacy `SkillMode`) is still written by the new
  launcher, so all existing reporting continues to work.
- No localStorage key or Firebase schema changed.
- Classroom membership falls back to the roster, so pre-v0.49 sessions
  scope correctly without being rewritten.
- `renderMaybeInStudentShell` retained as a legacy shim.
- Legacy `startForm` / `class6math` / `assessmentPicker` paths intact.

**A note on `purposeOf()`:** legacy sessions return `null`, not a
guessed purpose. Do not treat pre-v0.49 sessions as practice runs.

**A test-harness defect was found and fixed.** `globals: false`
disabled React Testing Library's automatic cleanup, so renders stacked
across tests, and jest-dom matchers were never registered — meaning
`expect(el).toBeDisabled()` threw "Invalid Chai property" instead of
asserting. Any v0.48 DOM test using a jest-dom matcher would have
been unreliable. Fixed by `src/test/setup.ts`.

## 8. Visual review — performed

Unlike v0.48, this was actually carried out. Chromium (Playwright
1.49.1) was installed, the production build served via `vite preview`,
and **55 screenshots captured: 11 screens × 5 widths (320 / 390 / 768
/ 1024 / 1440)** — student Home, Learn, chapter landing, lesson,
active practice, chapter check, Progress; teacher Overview, Insights,
Resources, Admin & Research. Horizontal overflow was measured
programmatically on every screen.

**The review found three real defects that the test suite did not:**

1. **12px horizontal overflow at 320px on every screen.** `NavBar`'s
   action row had no `flex-wrap`. Fixed → 8 affected screens to 0.
2. **A signed-in teacher who reloaded landed on the student shell.**
   The initial view was hard-coded to `'landing'` regardless of stored
   app mode. Pre-existing since v0.8; invisible without a cold-load
   screenshot. Fixed.
3. **Authoring metadata shown to students mid-question** —
   "Difficulty (seed): 2/10", the raw skill code, the
   cognitive-demand tag. A §14 violation my DOM tests missed because
   they only checked the shell tabs. Fixed, with 10 regression tests.

**Final state: 0 screens with horizontal overflow at any width.**
Touch targets on primary controls are `min-h-[44px]`. The bottom nav
retains its spacer, so content is not obstructed.

The screenshot tooling (`playwright`, `shots.mjs`) has been **removed
from `package.json` and the lockfile**; the verification above was run
after that removal.

## 9. Known remaining problems

1. **Only Class 6 Fractions has an executable blueprint.** Every other
   chapter offers practice but no chapter check — by design, not
   oversight.
2. **Screenshots were reviewed for layout, not pedagogy.** I checked
   clipping, overflow, touch targets, and hierarchy. Age-appropriate
   *tone* across Classes 1–12 still needs a human, and the
   `design/ageStage.ts` tokens remain unthreaded through shell copy.
3. **Save & Exit stores a short completed session** rather than a
   resumable one — the storage layer has no paused-session
   representation. A student who exits mid-set and returns starts a
   new set. This is a deliberate scope decision, not a silent
   limitation; a real resume needs a schema change.
4. Legacy `startForm` / `class6math` paths still exist and still
   render the older interface for teacher previews and first-run.
5. `TeacherOverviewBody` still passes hard-coded
   `studentsNeedingAttention={0}` and null labels.
6. The >500 kB bundle-chunk warning is unaddressed.
7. `ProgressTab` shows raw `skillId` values rather than friendly skill
   names.

## 10. What should NOT be claimed yet

- **Do not claim CBSE/NCERT alignment or verification.** All official
  chapter records remain `unverified` with null source references. No
  authoritative source was consulted in this iteration.
- **Do not claim Classes 1–12 coverage.** One official chapter record
  exists. Other grades have Pragati modules with no verified official
  chapter mapping.
- **Do not describe Pragati as a calibrated assessment.** Scoring is
  still a transparent heuristic over seed difficulties, not an IRT fit.
- **Do not claim sessions are resumable** (see item 3 above).
- **Do not claim age-appropriateness has been validated** for Classes
  1–5 or 9–12. No child or teacher has reviewed this.
- **Do not claim the chapter check is psychometrically valid.** It is
  a coverage-balanced practice instrument.
