# Pragati v0.48 — Stabilization report

Corrective iteration against the 12 defects called out after v0.47.
Honest §-by-§ status below. Screenshots (§12) are the one item I
cannot fulfil in this coding environment — I do not have browser
automation.

---

## §1 Chapter resolver — DONE

- New `src/curriculum/chapterResolver.ts` exports one canonical
  `resolveChapter(chapterId)` that handles verified official
  chapters, mapped official chapters, legacy Pragati module shells,
  and unknown IDs (returns `null`, never a silent default).
- Removed the `inventoryWithLegacyModule` push/pop that mutated
  `STATIC_MAPPING` at render time.
- `buildContentMapping(official, staticRow)` and new
  `inventoryChapterWith(official, staticRow)` both accept an
  explicit optional mapping — pure functions, no global mutation.
- Tests: `chapterResolver.test.ts` (7 tests). One explicit test
  asserts `STATIC_MAPPING.length` is unchanged after 10× resolutions
  of every kind of chapter id.

## §2 Student stays inside StudentShell — DONE (via wrapper)

- New `features/student/wrapInStudentShell.tsx` exposes
  `renderMaybeInStudentShell()`. In App.tsx the `assessment`,
  `results`, and `learningPath` view branches now render inside the
  shell via `sessionChild`, so the top + bottom nav stay visible.
- Test `StudentShell.dom.test.tsx` "session persistence" case asserts
  nav is still present while `sessionChild` renders.

## §3 Practice modes + Fractions blueprint — DONE

- New `curriculum/chapterBlueprints.ts` with an explicit
  `blueprintForChapter(chapterId)`. Only Class 6 Fractions returns a
  blueprint; every other chapter returns `null`.
- Practice tab (StudentShell) now renders three distinct buttons per
  chapter: **Practise one concept** (single skill), **Open chapter**
  (mixed practice), and **Chapter check** (only when a real
  blueprint exists).
- The "first-skill assessment mislabelled as chapter practice / check"
  bug is gone — App.tsx now translates a module id to `mixed_<module>`
  when that SkillMode exists, and only falls back to the first skill
  when the mixed mode is not registered.
- Tests: `chapterBlueprints.test.ts` (3 tests) — Fractions has a
  blueprint, no other chapter does, and the exported list of
  blueprints is exactly one.

## §4 Student data isolation by ID — DONE

- New `features/student/studentData.ts` with `sessionsForStudent`,
  `sessionsForStudentIn`, `progressForStudent`,
  `recentActivityForStudent`, all keyed on `studentId`.
- StudentShell reads via these helpers only (no more `.name` joins).
- Tests: `studentData.test.ts` "two students with the same name never
  share sessions" case.

## §5 Continue-learning correctness — DONE

- `findContinueTarget(studentId, studentGrade, {sessions?,
  launchableChapterIds?})` uses `MODULE_FOR_SKILL` + `MODULE_GRADE`
  to map the most-recent completed session's skill to its chapter;
  cross-grade / other-student sessions are ignored.
- When no valid recent chapter exists, the shell now labels the CTA
  "Start" (not "Continue"), and the greeting reads
  "Hi <name>, let's start" rather than "Welcome back".
- Tests: 6 cases covering no session, Fractions, another module,
  another student's session, cross-grade session, and picking the
  most-recent-of-many.

## §6 Real grade normalization — DONE

- New `src/lib/gradeNormalization.ts` with
  `normalizeGrade(input)`. Accepts `class6 / Class 6 / Grade 6 /
  grade_06 / grade_6 / 6 / "6"`. Rejects unknowns instead of
  defaulting.
- App.tsx now routes an unknown grade to a new
  `ProfileCorrectionScreen` instead of silently loading Class 6.
- Tests: 16 cases (every class 1-12 through every recognised format,
  plus explicit rejections for empty, out-of-range, and unrecognised
  strings).

## §7 Honest inventory counts — DONE

- `inventoryChapterWith(...)` now reads real registered blueprints
  via `getBlueprints(...)` and returns `registeredBlueprintIds: []`
  when none apply. `blueprintAvailable` is derived from that list,
  not from `assessmentItemCount > 0`.
- New `Measurement<T>` type — `visualCount`,
  `guidedPracticeItemCount`, `independentPracticeItemCount`, and
  `unresolvedValidationErrors` are now `'not_measured'` instead of a
  silent `0`.
- Readiness rules only look at actually-derived counts; a chapter
  cannot become `prototype_ready_review` on placeholder zeros.

## §8 Student copy — DONE (minimal)

- Removed developer / product-design language from `HomeTab`,
  `LearnTab`, `PracticeTab`, `ProgressTab` (previously included
  "One primary action per screen", "prototype content", psychometric
  warnings).
- Progress tab now shows a concise collapsible "About this result"
  disclosure instead of a page-wide caution block.
- Age-stage-specific tone (Classes 1-2 vs 9-12) is **partially
  addressed**: the tokens exist in `design/ageStage.ts` (v0.46) but
  are not yet threaded through every string in the shell. That is
  the next rewrite.

## §9 Teacher tab migration — DONE

- New `features/teacher/TeacherInsightsBody.tsx` (real body: recent
  sessions, overall accuracy, top misconceptions, weakest skills).
- New `features/teacher/TeacherResourcesBody.tsx` (grade selector +
  chapter list for the selected grade). Never routes to
  `class6math`.
- Removed the `false && (<TeacherWorkflowHome ...>)` dead-code
  branch. Legacy handlers no longer flow through App.tsx unused
  imports.

## §10 App.tsx reduction — PARTIAL

- v0.47 baseline: **2,752 lines**.
- After §10 extraction: **2,448 lines** (−304).
- Target: <2,000 lines. **Not met.** Extracted `Assessment`,
  `McqOptions`, and `NumericEntry` into
  `features/session/AssessmentView.tsx` (283 lines), removed 8 dead
  imports, deleted the legacy TeacherWorkflowHome branch (~90 lines).
- The remaining bulk is `SkillCard`, `Class6MathDashboard`,
  `ModuleDashboard`, `TeacherStudentList`, and the huge `startForm`
  / `assessmentPicker` render blocks. Extracting them without
  functional regressions is a bigger surgery; deferred to v0.49.

## §11 UI flow tests — DONE (subset)

- Installed `@testing-library/react`, `@testing-library/dom`,
  `@testing-library/jest-dom`, and `happy-dom`.
- `vitest.config.ts` now enables `plugin-react`, `.tsx` test files,
  and per-file `happy-dom` environment matching.
- New `features/student/__tests__/StudentShell.dom.test.tsx` (5
  tests) covers: StudentShell renders 4-tab nav; Admin & Research
  is NOT primary nav; Learn shows Fractions chapter cards; no
  "Chapter not available" copy leaks into the initial catalogue;
  StudentShell nav stays visible while `sessionChild` renders.
- Not written yet (listed for v0.49): grade-normalization DOM,
  Teacher Resources grade-awareness DOM, keyboard-label harness,
  zero-item-launch integration.
