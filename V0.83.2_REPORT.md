## The live defect

4. **Student.** `gradeCurriculumView()` knew the verified curriculum, but
   the screen never called it. `chaptersForStudentGrade()` built official
   rows from `OFFICIAL_CHAPTERS`, which was still Class-6-centric, and
   fell back to legacy Pragati modules for every other grade. A Class 3
   student saw **six legacy modules** where Maths Mela has **fourteen
   chapters**. Classes 1, 2, 4, 5, 7 and 8 behaved the same way. Every
   model test passed throughout, because they asked the model rather than
   the screen.
5. **Teacher.** Same stale path, plus a worse symptom:
   `TeacherResourcesBody` filtered its cards with `isClass6Core(...)`, so
   for every grade except Class 6 it rendered **no chapter cards at all**.
   Each card it did render offered "Open chapter resources" whether or
   not any resource existed.
6. **Now:** `OFFICIAL_CHAPTERS` derives its records for Classes 1-5, 7
   and 8 from `data/mathCurriculumMasterEvidence.json` — the same
   canonical evidence the master map and the runtime curriculum read. No
   row was hand-copied. Student, Teacher, `resolveChapter` and
   `ReadinessMatrix` all read that one registry.

## Mobile

14. **Cause:** the v0.83.1 harness clicked buttons by exact text match.
    The teacher-mode control's text node also carries the brand and the
    tab labels ("Pragati | Learn | Teacher dashboard"), so an exact match
    never hit it and Resources was never reached.
15. **Harness defect, not a product defect** — and it was failing at
    every width, not only 390. The 768 and 1440 rows had passed in
    v0.83.1 only because they never asserted anything after navigation.
    Evidence: the visible-button dump recorded in the failing run.
16. **Final 390px result: 24 of 24 rows pass** (12 Student + 12 Teacher).
    The phone bottom bar already carries Resources, so no product change
    was needed and none was made.
