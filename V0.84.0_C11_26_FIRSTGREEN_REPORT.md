## B. Corrected architecture claim — the binomial theorem is NOT used

The derivative implementation composes **limits** (ck86), **functions**
(ck81), **induction** (ck87) and **trigonometric semantics** (ck80).

It does not use the checkpoint-89 binomial model. The power-rule proof takes
the product-rule route: write x^(k+1) as x^k · x, differentiate the product,
and let the induction hypothesis supply the derivative of x^k. No expansion
of (x+h)^n is needed on that path.

An earlier report listed the binomial theorem as a composing system. That was
wrong, and the unused import was the evidence. It is removed rather than
kept to make the architecture look richer; a test now asserts the derivative
module imports no limit, induction or combinatorics implementation of its
own.

## C. Corrected domain-leak fixture

The first version expected the quotient rule to leak when built with an empty
exclusion list. It did not, because the rule guards a zero denominator
**independently** of that list — the model was stronger than the test
assumed.

The revised fixture is the valid one: a sum rule written over 1/(x − 1)
without carrying the restriction claims a slope at 1, and `validateRule`
rejects it as *widened the domain*. The first version would have passed for
the wrong reason.
