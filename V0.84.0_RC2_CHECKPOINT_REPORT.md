## A/B. Baseline and root cause

Checkpoint 44 source at `0.84.0-rc.1`: 93 units, 92 artifacts, 1 contextually
covered, 0 unresolved, all `authored_draft`, 0 sent/reviewed/adjudicated/published.

**The root cause was a mismatched source of truth.** `chaptersForStudentGrade()`
builds the student chapter list from assessment-item inventory and
`canLaunchAssessment()`. Class 9 has authored instruction and no item bank, so
every chapter evaluated as unavailable and the lessons had no door. The
artifacts were never the problem.

## C. Integration architecture

`authoredLearnCatalogueForGrade(grade)` derives the catalogue from the two
things that actually decide it — the verified official chapter registry and
the authored artifact registry. **No second lesson list exists**, so authoring
and the student catalogue cannot drift.

Three screens in `AuthoredLearn.tsx` (chapters → lessons → lesson), reached
through the existing `learnOverride` seam that Class 6 already uses. No new
shell, no React Router, no second renderer.

## D. Governance boundary

All 92 remain `authored_draft`, and the eligibility policy that keeps
unreviewed content from students is **unchanged**. `isAuthoredLearnPreviewable()`
states a narrower claim: an authored lesson is reachable on the student
preview route used for RC validation. Publication eligibility is a separate
question, still answered elsewhere, and still false for all 92.

Reachable in the RC never becomes published.

## E. Artifact identity

Routing is keyed on **`contentArtifactId`**, never `officialSectionId`. Tests
prove it matters: more than five official sections split into multiple
lessons, which a section-keyed route would collapse, and merged lessons carry
`additionalOfficialSectionIds`, which a section-keyed route would duplicate.

## F/G/H. The catalogue

**14 chapters, 92 lessons**, in printed order.

**Chapter 3 shows 8 lessons.** No phantom §3.1, no missing slot. The first
lesson is the revised §3.2 at version 2, carrying the contextual opening.

**Chapter 9 shows 2 lessons.** Segment-backed, with no fabricated section
numbers — `learnContentFor()` is now source-kind aware, so an empty
`officialSectionId` no longer queries a misconception key no section owns or
prints " · " where a number should be. It uses the chapter's own printed
title.

## I/J. Splits, merges, renderer

Split siblings appear separately with distinct route keys; merged lessons
appear once. Lesson rendering calls `learnContentFor()` then
`LearnSectionView` — the same pipeline the review preview uses, asserted by
test rather than by intention.

## K/L. Progress and denominators

Progress is tracked by `contentArtifactId` in `learnProgress.ts`, scoped per
student, in local storage. Completion is explicit: a **Finish lesson** control
appears only on the final stage, so opening a lesson never completes it.

**Denominator 92, not 93.** A test completes all 92 and asserts `92/92` and
100%. Chapter denominators come from artifacts: Chapter 3 is 8, Chapter 9 is 2.

## M/N. Home, Learn and Practice

The Learn tab no longer consults item inventory for Class 9, so the
item-derived false negative is gone. **Practice was deliberately not
touched** — Class 9 has no item bank, and manufacturing one because Learn now
works would be the same category error in reverse.
