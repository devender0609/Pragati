## 1. The fixture

Eight students, six sessions across five real FR.02 items, one active
and one closed assignment, one class. Activity is deliberately uneven —
two recent, two a fortnight old, two who have never worked — because a
fixture where everyone is equally active hides the case Insights exists
to surface.

`tools/teacherFixture.mjs`, seeded into localStorage by the capture
harness. **No production file imports it.** Nothing derived is seeded:
no mastery, ability, proficiency or growth value, and `finalAbility` is
written as 0, so no screen can display a measure with no source.

## 2-8. What populated review found

Every defect below was found by opening a picture. None was visible in
an empty state, and none would have been caught by the test suite.

**Classes** printed **"Latest band: Foundational"** and **"Latest est.
0.0 / 10"** eight times down the roster — a proficiency classification
and a 0-10 measurement, in a product whose own footer says it produces
no calibrated score. Both removed from normal Teacher; `computeBand` and
`finalAbility` stay for Admin.

**Insights** showed teachers `counts_shaded_only` and `FR.02` — our
identifiers, not names — and headed a panel **"Weakest skills"**, a
verdict on students derived from a percentage. Now "Where responses may
be worth reviewing", with authored labels. The unmapped-code fallback no
longer prints the code either, because it is the unmapped case that
slips through review.

**Overview** asked **"Which skills were difficult?"** and answered
**"Revisit X — it has the lowest recent accuracy"**. Difficulty is a
property of the mathematics; a count of wrong answers is a property of
the responses. Now "Where did answers go wrong most often?" and "Worth a
closer look?", with the judgement left to the teacher. Its assign panel
also rendered only in the empty branch, disappearing exactly when a
teacher starts asking what to assign.

**Assign** chips read **"FR.02 — Visualise"**: the internal code first,
the human words second. Right order for an item-bank audit, wrong one
for a teacher's own assignment list.

**Assess** was still a Growth setup with a disclaimer above it — three
screens of wizard for a track the same page says is not operational,
while the everyday check had a route but no room. The setup is folded
now, not deleted: Growth is governed, not gone.

**Insights' safeguard rendered only when empty.** §11 asked to reduce
its prominence; data was deleting it. It is now one "How to read these
numbers" disclosure in both states — closed a line, open the same three
limits word for word.

## 9-12. The other lock conditions

`TEACHER_STATUS_LABEL` maps every build state to one of four things a
teacher can act on. `DERIVED_STATUS_LABEL` untouched for Admin, and a
test asserts the teacher map never says "prototype", "shell only",
"pilot-ready" or "Ready to learn". Raw skill codes are out of
`withheldReason`. Legacy disposition is one sentence with the audit
trail in Admin. Resources leads with what can be taught; the governance
pointer moved to the bottom. The calibration caveat is an "About these
results" disclosure — same words, in the DOM, once per screen instead of
shouted under all six.

## Two contracts changed on purpose

The Assess route contract required the literal "Separate from everyday
practice". That sentence lived inside the Growth setup's own subtitle —
the separation was stated only *inside* the thing it separated from, so
folding the setup took it with it. The obligation is unchanged and now
sits above both tracks, before either is offered, checked by three
strings instead of one. Its unit test was updated in the same way, with
the reasoning written in both files.
