## 1. Why the source inventory still showed 65 under Topics

v0.82.4 fixed the coverage matrix and left the source inventory with a
single cell computed as `officialSections ?? officialTopics` under a
column headed **Topics**. For Class 6 the first operand was 65, so 65
was printed as topics.

And the v0.82.4 test did not catch it. It checked that each document's
Class 6 row *contained* 10 and 65 — which the inventory row did, in the
wrong column. **A test whose description claims more than its assertion
proves hands out false confidence**, and that one said "the documents
agree" while they did not.

## 3. The test now reads cells by header

`cellsByHeader()` finds the row, then the **nearest hierarchy header
above it**, maps column names to indices, and reads the cell under a
named column. It asserts `Units = —`, `Chapters = 10`, `Sections = 65`,
`Topics = —` for Class 6, and the equivalent for Class 9 and Class 10,
across all three documents.

"Nearest above" mattered: the structure backlog holds two tables with
different columns, and reading the first header in the file misaligned
every column of the second — a new version of the same bug, caught by
the test itself on its first run.

## 4. The evidence note

Was: *"a trustworthy topic-level denominator as well as a unit-level
one."* Both levels invented.

Now: *"a trustworthy chapter- and section-level denominator. The book
defines chapters and sections; it has no unit layer and no topics."*
