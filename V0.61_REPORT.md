## 4. Middle vs Secondary Stage correction

NCF-SE states goals **per stage**: Middle (6–8) CG-1..CG-10; Secondary
(9–12) CG-1..CG-11. v0.52 built the framework from the CBSE Class IX
document — the **Secondary** set — and applied it to Class 6.

**Nine of fifteen constructs require action.** Not a renumbering:

- **Meaning changed (6):** numbers, exponents, algebra, geometry, area, data
- **Number only (3):** computational thinking, history, cross-subject
- **Middle only (2):** puzzles CG-7, compass-and-straightedge C-3.4
- **Secondary only (2):** probability, modelling

`ncfStages.ts` makes the error structurally impossible: IDs are
stage-qualified (`MIDDLE:C-1.4`) and `competencyValidForGrade()` rejects
a Secondary citation on a Class 6 unit.

### Probability — precise wording

> NCF-SE Middle Stage Mathematics does not explicitly specify
> probability as a competency in the MIDDLE:CG-1..MIDDLE:CG-10 block. A
> full-text search of Ganita Prakash Grades 7 and 8 returns zero
> occurrences of "probabilit*".

This is **not** a claim that probability is absent from Middle Stage
education generally. No probability reporting domain was created.

  asserts no `deriveXFromY` function exists.

  statuses (official verification / Pragati mapping / competency

  student-facing gate was loosened.**

reads "9 official sections · 5 with content · 4 unmapped · 0
educator-reviewed". A test fails if a `percent` field appears.

## 8. Demonstration section and visual system

**Ganita Prakash §7.4** (p. 160) — a real gap in the reference module,
realising the named competency `MIDDLE:C-1.4`.

5 worked examples with per-step reasoning · 4 misconceptions with
student feedback and teacher notes · guided, independent and reasoning
practice · teaching notes · questioning prompts · struggling-learner
support · extension · answer rationales.

**Status: `authored_draft`.** Not published, not student-visible.

### Two content bugs found and fixed

**WE4** had Aarav reach the *right* answer by faulty reasoning, so the
example refuted and affirmed its own conclusion. Rewritten: he claims
1/4 > 1/3 because 4 > 3, and the example refutes it. Tested for
prompt/answer/reasoning consistency.

**Fraction strips** — the reported symptom was close but the arithmetic
differed. Under index semantics the data was correct (1/2, 2/4, 4/8);
read as denominators it gave 1/1, 2/2, 4/3. **The data was not wrong,
the schema was**: keys and row values were both plain numbers, so a
renderer had to guess. Replaced with `{denominator, shadedCount}` plus
`assertsEquivalence`, which validation checks arithmetically rather than
trusting the caption.

**§9 documentation corrected.** The "never floats" claim contradicted
`positionOnLine()`. Now: numerator/denominator is canonical and all
curriculum semantics use exact integer arithmetic; floats derive screen
coordinates only; no curriculum claim may rest on float equality.
