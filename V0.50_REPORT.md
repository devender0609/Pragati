## 3. Issues corrected

### §1 Save & Exit — resumable sessions implemented

v0.49 said "come back later" and wrote `completedAt = Date.now()`. Three
consequences: the promise was false; a chapter check abandoned after 2
of 10 was stored as a **completed** check; and every analytic filtering
on `completedAt !== null` absorbed partial attempts as finished work.

Now: `Session.lifecycle` is `in_progress | completed | exited`, all
fields optional so pre-v0.50 records load unchanged. Progress persists
after **every answer**, so a closed tab resumes. Home shows **Continue
practice** with the count remaining. `isCompletedAttempt()` is the only
predicate analytics use.

Legacy sessions with `completedAt` set read as `completed`. We cannot
retroactively tell which v0.49 records were abandoned early — stated
here rather than papered over.

### §2 Mixed practice is genuinely mixed — worse than reported

The brief said the launcher "may fall back to the first skill." In fact
only Class 6 and 7 modules have a `mixed_*` SkillMode, so **every module
in Classes 1–5 and 8–12** administered a single concept under a "Mixed
practice" label.

New `ModulePracticeBlueprint` derives a runtime plan from the module
registry: gathers all registered skills, keeps only those with items,
samples **breadth-first** (round-robin, so no skill runs more than one
item ahead), prefers fresh items. Below two usable skills the label
changes to **Practise this concept**; with none, the action disappears.
Kept separate from ChapterBlueprint — generic practice can never be
promoted into a chapter check.

### §3 Concept practice is a real choice

v0.49 launched `skillIds[0]`. Now a chooser lists concepts by
student-friendly name with New / Practised / Review recommended. Skill
codes never appear. A chapter with exactly one usable concept launches
directly.

### §4 Chapter-check readiness gate

A check may launch only when every required skill has an eligible item,
the pool samples every required skill, and the pool reaches
`targetItemCount` (or an explicitly declared `minimumItemCount`).
Otherwise: *"Chapter check isn't ready yet. You can keep practising this
chapter."* Practice is deliberately exempt — it claims no chapter-level
coverage. Sessions persist requested count, administered count, and
missing required skills.

### §5 / §6 Student-facing copy

`STUDENT_STATUS_LABEL` gives students *Ready to learn / Practice
available / Coming soon*; the authoring vocabulary is preserved
unchanged for teacher and admin surfaces. The footer disclaimer now
renders **only** in teacher mode. Progress shows friendly concept names
via `friendlySessionLabel()` — never `FR.02` or `mixed_fractions`.

### §7 / §8 Teacher analytics

`studentsNeedingAttention={0}` was a hard-coded literal rendered as
"Nobody on the flag list right now" — a placeholder presented as a
finding. Now evidence-based with explicit exported thresholds (6+
attempts before any accuracy signal; 3+ repeats before a misconception
is reported; 5+ attempts before a skill is called difficult).

The key distinction: `[]` means "we looked, nobody qualifies"; `null`
means "not enough evidence" and renders **"Not enough recent activity
yet."** v0.49 collapsed both into 0. A persistent class selector in
TeacherShell keeps Overview, Insights, Assign, and Resources on one
scope.

### §9 / §11 Age-stage composition

Tokens existed but were used in one component. Added `STAGE_LAYOUT`
governing what is *shown*, not just sized: chapter columns (1 / 2 / 3),
chapter art on/off, Home secondary-item cap (0 / 1 / 2 / 3), concept
lists, numeric progress, exam framing, and primary-action wording
("Learn" → "Start learning" → "Continue where you left off"). Home
gained stage-capped secondary context; early primary shows none.

### §12 First-run paths

A new user's "Learn" went straight to the legacy Class 6 dashboard
whatever their class. Now: no profile → canonical onboarding; existing
student → their own shell. Legacy views remain for deep links only.

### §13 Accessibility

13 automated assertions over rendered DOM. These **found real defects**:
chapter cards, teacher grade-selector pills, desktop nav tabs, the mode
toggle, language switcher, and brand button were all below 44px; and
`h1 → h3` skipped a heading level in ChapterCard and EmptyState.

### §14 Content-loading architecture

`contentRegistry.ts` establishes chapter-level addressing
(`curriculum/cbse/grade-06/mathematics/fractions`), a memoised lazy
loader, and a legacy adapter. **No content moved** — a test asserts
`CURRENT_MIGRATION_STEP === 'registry_and_loader'` and that the registry
is empty, so the claim cannot silently become false. Six-step migration
plan with rollback documented in the module.

## 4. Official curriculum verification (§15 / §16)

### The finding

**NCERT replaced the Class 6 mathematics textbook.** The current book is
**Ganita Prakash** (10 chapters, NEP 2020 / NCF-SE 2023). Pragati's
Class 6 modules were built against the **old 14-chapter** *Mathematics*.

| Pragati module | Status in Ganita Prakash |
| :--- | :--- |
| `fractions` | Chapter 7 "Fractions" — exact |
| `factors_multiples` | Partial — nearest is Ch 5 "Prime Time" |
| `geometry` | Partial — split across Ch 2, 6, 8, 9 |
| `decimals` | **No standalone chapter** |
| `ratio_proportion` | **No standalone chapter** |
| `algebra` | **No standalone chapter** |

Half the Class 6 module set has no corresponding chapter in the textbook
schools currently use. Fractions mapping cleanly at Chapter 7 in *both*
books is why this stayed invisible.

The three unmappable modules are recorded in `UNMAPPED_LEGACY_MODULES`
with their old-book chapter, rather than being forced onto a
plausible-looking current chapter.

### Exact source, and its limits

- **Confirmed on the publisher's own domain:**
  `https://ncert.nic.in/textbook/pdf/fegp1ps.pdf` — "Textbook of
  Mathematics for Grade 6 GANITA PRAKASH Reprint 2026-27". This
  establishes textbook, grade, and edition.
- **Not confirmed from the primary source:** the 10-chapter list.
  `ncert.nic.in` serves robots.txt rules blocking automated retrieval,
  so the PDF could not be read programmatically. The chapter list comes
  from several independent secondary sources that agree exactly.

All ten records are therefore **`secondary_corroborated`**, a new status
between `unverified` and `source_verified`. **No record is marked
`source_verified`.** `validateOfficialChapter()` rejects any verified
status missing its required source fields.

**What a human must do:** open that PDF and confirm the chapter numbers
and titles. Only then may these advance.

The legacy placeholder ID resolves through `CHAPTER_ID_ALIASES`, so
stored sessions and the existing blueprint keep working while the
catalogue shows one canonical Fractions chapter.

## 6. Visual review (§19)

45 screenshots: three stages (Class 1 / 6 / 12) × Home and Learn, plus
teacher Overview / Insights / Resources, at 320 / 390 / 768 / 1024 /
1440. Overflow and touch-target size measured programmatically.

**Found four defects the test suite did not:**

1. **289px horizontal overflow at Class 12 Learn.** The grid declared
   only `sm:grid-cols-2 lg:grid-cols-3` with no base `grid-cols-1`, so
   CSS fell back to one implicit column sized to `max-content` and long
   titles blew out the row. Introduced by my own §9 work. Fixed across
   14 files.
2. **Sub-44px controls** in nav chrome, chapter cards, and the teacher
   grade selector.
3. **Status contradicted the action** — cards read "Practice available"
   beside a "See status" CTA. Also mine, from the §5 label mapping.
   Fixed, with a regression test.
4. **Titles clipped mid-word** when sharing a flex row with the status
   badge. Title now takes its own full-width row.

**Final state: 0 overflow and 0 undersized targets across all 45.**

Stage differences are visible: Class 1 renders one full-width column
with large artwork; Class 12 renders three columns with denser rows and
no artwork emphasis.

## 7. Remaining limitations

1. **Chapter list not primary-source verified** (§4 above). This is the
   single most important open item.
2. **§10 visual richness only partly addressed.** Chapter artwork,
   stage-based layout, and hierarchy improved; visual learning paths,
   progress graphics, and completion feedback were **not** built.
3. **Bundle still >500 kB.** The architecture for splitting exists; no
   content has moved, so the warning is unchanged and expected.
4. **Legacy Class 6 sessions cannot be reclassified.** Records written
   before v0.50 with `completedAt` set read as completed even if they
   were abandoned.
5. **Class 1–5 and 8–12 chapters remain unverified placeholders** with
   generated titles. They are not official curriculum.
6. **Age-stage tone not reviewed by a teacher or child.** Layout differs;
   whether it is *appropriate* is unvalidated.
7. **No Hindi content review.** The switcher works; translated
   curriculum has not been checked.

## 9. Recommended v0.51 plan

The research changes the order of work. Content authoring against the
current module structure would produce material that does not match the
textbook in use.

1. **Human-verify the Ganita Prakash chapter list** from the official
   PDF. Advance the ten records to `source_verified`. Blocks everything
   else.
2. **Decide the Class 6 module question.** Three modules (`decimals`,
   `ratio_proportion`, `algebra`) have no current Class 6 chapter. Are
   they retired, remapped to the grade where that content now sits, or
   kept as supplementary practice outside the chapter catalogue? This is
   a curriculum decision, not an engineering one — it needs you.
3. **Author the Ganita Prakash chapters Pragati lacks** — Patterns in
   Mathematics, Number Play, Data Handling, Perimeter and Area, Playing
   with Constructions, Symmetry, The Other Side of Zero. Start with one
   to prove the authoring pipeline.
4. **Execute migration Steps 1–3** (`contentRegistry.ts`): move
   Fractions dual-source, verify identical output, remove the bundled
   copy, measure the bundle.
5. **Repeat the chapter-structure check for one other grade** before
   assuming any grade's module set matches its current textbook.
6. Only then begin multi-grade authoring.
