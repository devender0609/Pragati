## 4. Teacher assignment (§3)

`onAssign` now calls `prepareGrowthAdministration()` → verifies
`ready` → `createFormalAssignment()` → persists → refreshes state.
**Production remains blocked upstream**: preparation refuses without an
approved framework, so creation returns `ok: false` and nothing is
persisted. The path is wired, not faked.

## 5. Assignment model (§4)

The active formal workflow uses `FormalGrowthAssignment` throughout —
panel, card, App state, instructions, sitting.

## 6. Student Begin (§5)

Begin now calls `startFormalSession()`, persists to the session store,
and routes to a dedicated `growthSitting` view. It no longer returns to
landing, and it never touches practice infrastructure.

## 7. Session persistence (§6)

`formalSessionStore.ts` persists session ID, assignment, student, frozen
form and order, position, responses, timings, interruption and resume
counts, supports, and the configuration snapshot. `containsSecureContent()`
**throws rather than persisting** if stems ever reach it — a stored
session is browser storage, and secure content does not belong there.

## 8. Formal item screen (§7)

`FormalSittingView` is a separate component, deliberately. Reusing the
ordinary Assessment view and hiding its hint disclosure would mean every
future change to that component risks leaking instructional behaviour;
this screen has no such code to disable. It renders only
`currentItemId()` resolved against the authorized bank, and **refuses
rather than substituting** when an ID cannot be resolved — skipping
would silently shorten the form.

## 9. Response recording (§8)

Submit calls `recordFormalResponse()` with item, response, omission,
elapsed time, timestamp, and exposure, then advances the frozen order.
No reassembly, no adaptive selection.

## 10. Exposure model (§9)

Split into `fieldTestAdministrations` and `operationalAdministrations`,
both **optional** so pre-v0.59 records load without producing NaN.
Legacy generic `growth` counts as field test, since no operational
administration has ever run.

## 11. Pause / resume / abandon (§11, §12)

Pause preserves state and returns Home; Home then shows **"Continue your
Growth Check"** instead of Start. Resume calls `resumeFormalSession()`,
which returns the identical session and form — there is no code path
from resume to the assembler. Abandon requires confirmation, keeps
partial evidence, and is distinct from completion. An expired window
blocks both start and resume.

## 12. Completion (§10)

Status set, persisted, `fieldTestOutcome()` generated, `GrowthComplete`
rendered. A test asserts the screen contains no *percent*, *score*,
*mastery*, *percentile*, *level*, or *correct*.

## 13. Supports (§13)

Session start looks up `supportsByStudent` for the active student and
snapshots the IDs with their comparability at administration time.

## 14. Legacy quarantine (§15, §16)

`buildGrowthPool` → **`legacyBuildGrowthPoolForCompatibilityOnly`**. No
production module imports it; it survives only so its historical
behaviour stays under test. This exact duplicate-path pattern is what
let the tested architecture diverge from the running product in v0.56.
