## Correcting v0.83.2 first

**v0.83.2's "72/72 curriculum QA" did not verify all twelve classes.**
Its comparison set was `[1, 2, 3, 4, 5, 7, 8]`. For Class 6 and Classes
9–12 the harness wrote `expectedCount: null`, `renderedCount: null`,
`titleMatch: null`, `orderMatch: null`, `availabilityMatch: null` and
`launchGuardMatch: null`, and those rows still counted as PASS because
no generic note had fired. Five of twelve classes were recorded as
verified without a single curriculum comparison being made.

That is recorded here rather than quietly fixed. In v0.83.3 a row cannot
pass on a null: `result` is PASS only when the title match, the order
match and the launch guard are all explicitly `true`. The JSON in
`qa-results/v0833-curriculum-qa.json` contains **0 rows with a null
curriculum assertion**.

borrows the lesson's fingerprint. It binds to the official section, the
book and verified page, and the mapping snapshot the specialist saw.

### What was actually broken, and is now fixed

- **Package A contradicted itself.** `IDENTITY.md` and
  `curriculum-evidence.json` said 159 while
  `PACKAGE_A_CURRICULUM_QUESTIONS.md` still printed 160. Corrected, and a
  regression test now scans **every file of every CURRENT package** for
  superseded pages and codes.
- **The v0.83.2 "end-to-end import test" imported nothing.** It used
  `reviewerRole: 'grade6_math_educator'` (not a role in the schema) and
  responses shaped `{rating, comment}` instead of `{decision,
  rationale}`, then asserted only that identity errors were empty — which
  they were, because the submission never reached the identity checks.
  Real submissions now assert `ok === true`.
- **Provenance could be bypassed by omission.** A package that declares a
  provenance identity now rejects a response without one.
- **Section packages printed provenance but did not check it.**
  `sectionReviewRecord()` now sets `expectedProvenanceFingerprint`, and
  the Chapter 3 and Chapter 7 `index.json` manifests publish content
  fingerprint, provenance fingerprint, provenance version, artifact
  version and question-set version.
- **The candidate manifest was insufficient.**
  `review-candidate.json` now carries `sourceProvenanceFingerprint`,
  `sourceProvenanceVersion` and `reviewCode`, so the machine-readable
  file alone identifies the artifact and its provenance.
