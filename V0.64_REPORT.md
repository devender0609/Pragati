## 0. Correction to the v0.63 report

**The v0.63 report overstated section-aware progress.** It listed
"Progress section-aware — Yes" among the met stop conditions. In fact
`sectionProgressForChapter()` had **zero non-test callers**; the real

## 1. Is the actual Student Progress UI section-aware now?

**Yes.** The Progress tab renders the nine official Fractions parts with
factual states — Not started / In progress / Practice completed — plus
the date of last activity, a Continue button addressed by official
section ID, and recent activity retained below as secondary detail.

Verified in the captured screenshot, not only by test.

Activity that cannot be attributed to an official section is shown as a
count ("you also have N earlier practice sessions not linked to a part of
this chapter") rather than dropped, so history does not appear to shrink.

## 2. Are raw skill codes gone from Class 6 student screens?

**Yes.** A render test walks **every** Class 6 chapter interior and
fails on `/\b(FR|GB|DE|RP|AL|FM|LA|NP)\.\d{2}\b/`.

That test caught a live leak: `decimals` was still reachable as a legacy
chapter row and rendered `DE.01`–`DE.05` under "Concept map" plus "0 of 5
skills strong". Fixed at the **routing layer** — `ChapterDetail` now
refuses a displaced legacy module for Class 6 — rather than only in the
list that happens to feed it today.

## 3. Is "skills strong" gone from the official Class 6 pilot?

**Yes**, along with the percentage journey ring derived from
`computeSkillProgress`. Replaced by counts of real things: "9 parts · 4
you can work on now", "0 of 9 parts started".

The `strong` engine is untouched — this was a presentation change, not a
data deletion. It remains in non-official grades, which is a known
inconsistency and named in §14 below.

## 4. Does an official chapter still depend on a legacy module to define its UI?

**No.** This was the core change.

Before: official chapter card → `resolveChapter()` →
`primaryLegacyModuleId` → `ChapterLandingPage(moduleId)`. The chapter was
official; its interior was a module experience structured by the
module's skills.

Now: `OfficialChapterLanding` takes an `officialChapterId` and derives
everything from the verified section registry. It is **reusable, not
Fractions-special** — a test renders Chapter 1 (no content at all) and
confirms it shows the official structure with an honest empty state
rather than a not-found.

Legacy modules still *supply* content behind an eligible section. They no
longer *define* what the child sees.

## 5. What now determines chapter Practice availability?

Previously `skills.length > 0` — a registered skill with zero questions
would advertise Practice. Now, where the official section map exists,
chapter status **rolls up from section eligibility**, so there is still
one decision-maker (§14). Where no section map exists, it requires actual
items.

## 6. Is educator-reviewed still incorrectly treated as student-ready?

**No.** v0.63 had `studentReady = reviewed`. Both were zero so nothing
broke, but the identity was wrong and would have become a live defect the
moment a reviewer approved an alignment.

`isSectionStudentReady()` is now a conjunction of four gates: release
permitted by adjudication · alignment educator-reviewed · a student-facing
artifact exists · instructional readiness passes. A test confirms §7.4
would still be refused even with a reviewed alignment, because its
release gate has not passed.

## 7. Does assignment identify concrete instructional activities?

**Yes.** `mayAssignSectionActivity()` now returns an
`InstructionalActivity` — `activityId`, `activityType`,
`officialChapterId`, `officialSectionId`, `provenance`
(legacy_module / authored_section), `itemCount` — with skill IDs demoted
to metadata. "Assign FR.03, FR.05" never said what the student would
receive.

## 8. Does Fractions remain inside StudentShell?

**Yes.** Opening a chapter now routes through `openChapterId` within the
shell instead of an App-level view. Home / Learn / Practice / Progress
stay visible; confirmed by test and by screenshot at all three widths.

## 14. What remains before authoring Fractions §7.1–§7.9?

1. A real Package B review, ingested and adjudicated.
2. Corrections implemented and re-verified.
3. Package A resolution for anything touching alignment.

**Deliberate removal requiring a decision:** the whole-chapter check is
gone from official chapters. Pragati covers 4 of 9 sections, so a check
labelled as covering the chapter would test less than half of it under a
whole-chapter name (§7). Reinstating it needs honest labelling —
"practice across the parts we cover" — which is a product decision, not
an engineering one.

**Known inconsistency:** Classes 1–5 and 7–12 still use the legacy module
page with skill codes and "strong". Only Class 6 has a verified section
registry, so extending the official interior to them would require
inventing structure. Correct for now; it should not persist.

## §16 Package A vs Package B dependencies

Declared per gate in `reviewDependencies.ts`, because the risk runs both
ways — B silently settling a curriculum question, or unrelated A items
stalling a narrowly reviewable §7.4 change.

| Gate | Owner | Blocked by A? |
| :-- | :-- | :-- |
| section_alignment_confirmed | A | Yes |
| instructional_quality_7_4 | B | **No** |
| legacy_module_disposition | A | Yes |
| section_7_4_publication | B | Yes (needs both) |

§7.4 instructional review can proceed now. Publication cannot.

## Tests changed, and why

Three tests in `chapterCards.dom.test.tsx` encoded superseded behaviour.
Each was updated with the reason inline, none deleted:

1. "launchable chapter shows Learning journey / What you will learn" —
   legacy-page copy. Intent preserved (a launchable chapter renders a
   real experience, never a not-found); accepted wording widened to
   include the official interior and the curriculum refusal.
2. "Class 6 Fractions offers a chapter check" — **inverted**, because the
   behaviour it required is the one §7 forbids.
3. "a launchable chapter with no blueprint says the check is not ready" —
   every Class 6 chapter is now official, so none renders the legacy copy;
   rewritten as "advertises no undeliverable action".
