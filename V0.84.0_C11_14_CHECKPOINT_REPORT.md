# 0.84.0-c11.14 — checkpoint 84C: shared layout verification

## U. Verdict — `CLASS_11_STRAIGHT_LINES_AUTHORING_PILOT_READY_FOR_HUMAN_REVIEW_GENERAL_LINE_SEMANTICS_EXTENSION`

Every gate passes. Nothing has been human-reviewed.

The checkpoint closes on a different finding than the one it was called for.

## A/B. Root cause — there was no layout defect

The brief said to verify before changing, and that is what settled it.

The persistent bottom nav is **60px**, fixed, `sm:hidden`. `BottomNavigation`
already renders its own **64px spacer**, on top of the lesson container's
`pb-20` (80px). Measured at the end of scroll, the lowest control clears the
nav by **124–125px** against an 8px minimum.

The 84B "3px overlap" was a measurement at scroll position 0 of a
**mid-document** control sitting beneath a floating bar that the reader simply
scrolls past. The content was always reachable.

One detail mattered: `window.scrollTo` inside an evaluate is silently ignored
by this layout, which is why 84B never reached the end of the page. A real
wheel event scrolls it to 866 and the control clears entirely.

## C/D. Layout fix — none made

**No padding changed. No magic number bumped. No shared constant introduced.**

Changing `pb-20 → pb-24` would have papered over a measurement error and left
a false entry in the layout history. The nav spacer (64px) already exceeds the
nav height (60px), so the two are not in drift.

## E. Detector repair

`tools/browser-qa/bottomClearance.mjs` replaces the noisy detector. It:

- requires `offsetParent !== null`, so collapsed and hidden controls are out
- requires non-zero rects and checks computed `display`, `visibility`, `opacity`
- scrolls to the end with a **real wheel event** before measuring
- compares the lowest visible control's bottom edge to the nav's top edge
- reports control label, control rect, nav rect and the calculated gap — not a count
- asserts `navTop − controlBottom >= 8`

It also reports "nav hidden at this width" rather than silently passing at
1280 and 834, where the bar does not exist.

## The defect this checkpoint actually found

**`VennSpec` had no branch in the renderer dispatch.**

Built at checkpoint 79, validated, attached to **8 figures across 6 Sets
lessons** — and rendering nothing for five checkpoints.

This is exactly the defect checkpoint 82 found in two graph specs. The
four-layer rule it established has caught every *new* spec since and never
looked back at the oldest one. Asking "does Venn still render?" is what
exposed it.

`VennDiagram.tsx` now draws the universe rectangle, both sets, and shades the
region the spec names — so the picture cannot claim a region the semantics did
not. The description is restated in the caption, so shading never carries
meaning alone.
