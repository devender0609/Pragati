## F/G. The set semantic model — architecture verdict **B**

`setTheory.ts`. A general set extension was required and was introduced
successfully.

**A set is a tagged union, not an array.** `explicit` carries members,
`interval` carries endpoints with structured inclusion, `described` carries a
rule and nothing else. The obvious `elements: string[]` cannot hold ℝ, cannot
hold an interval, and makes `{1,2,3}` and `{3,2,1,1}` different objects.
`isMember` **throws** on a described set rather than guessing — the same
refusal `sampleSpace` makes when equal likelihood is not established.

**`complement` requires a universe and throws without one.** Verified: the
call with no universe raises rather than returning something. That is the
hard invariant the checkpoint asked for.

**A Venn region knows which expression it is.** `VennSpec.shaded` names
regions by expression (`A_and_B`, `outside_both`), and `regionMembers`
computes what each contains from the sets. Shading is a rendering of the
expression, never an independent claim. `shadedNotation` returns what a figure
asserts, so prose can be checked against the picture.

Verified on the canonical data: union `{1,…,8}`, intersection `{4,5,6}`,
`A−B = {1,2,3}` and `B−A = {7,8}` **differ**, both De Morgan laws evaluate
true on both sides, and the counting relation reconciles —
`n(A)+n(B)−n(A∩B) = 18+12−6 = 24 = n(A∪B)`, with 2 outside.

`VennSpec` joined the shared `VisualSpec` union with the same `type`,
`altText`, `caption` and `status` contract as every other spec, rather than
living as a Chapter-1 special case. It is reusable for Chapter 2 relations and
Chapter 14 event algebra, which is why nothing in it mentions Chapter 1.
