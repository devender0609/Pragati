## A/B. Baseline and root cause

Checkpoint 81 was incomplete solely because the browser, viewport and
accessibility gates never ran. The harness drove the wrong state and failed
**silently**: it walked the 4-step onboarding wizard and set a grade `<select>`
that creates a teacher classroom, never a `Student` record. The app fell back
to Class 6, and the script happily reported "stages 1/5" against a welcome
screen. An earlier attempt also touched `localStorage` on `about:blank` and
threw `SecurityError`.

Nothing was wrong with the product's grade handling. The harness was.

## C. The real source of truth

Read from source, not assumed. `App.tsx` resolves the active student as the
selected one or `students[0]` from `loadStudents()`, and opens Learn only when
`normalizeGrade(active.grade)` is truthy. So the authority is the persisted
`Student` record in `pragati.students.v1`.

`pragati.selected_grade.v1` is **not** the authority — it belongs to the legacy
Class 6 dashboard and the assessment picker. A regression test now asserts that
setting it changes nothing about the active grade.

## D. The repair

One reusable module, `tools/browser-qa/studentFixture.mjs`, not another script:

1. navigate to the origin **first**, so storage exists
2. clear only the fixture keys this harness owns
3. seed one canonical `Student` in the real persisted schema, plus
   `pragati.app_mode.v1` and `pragati.onboarding.v1`
4. reload, so React re-initialises from storage
5. enter Learn through the real student route
6. **assert a product-visible consequence** — the rendered grade line — and
   throw if Class 6 appears

No test-only product bypass was added. No `?grade=` parameter, no hidden
switch. The harness adapts to the product contract.

## J/P. The product defect this gate found

**`VisualSpec` contained neither `circular_graph` nor `real_function_graph`.**
Checkpoint 80 built the first, checkpoint 81 the second, both were attached to
lessons — and the renderer's dispatch had no branch for either, so **every
Class 11 function graph rendered as nothing at all.** Before the fix the
standard-functions lesson showed 14 SVGs, all decorative icons, 0 named.

Unit tests validated the graph *data* and passed. No test asked whether the
product could display it. This is precisely the class of defect a browser gate
exists to catch, and it had survived two checkpoints.

**Fix:** both specs added to the union and to `validateVisual`, and one
component, `BranchedGraph.tsx`, renders both — they agree on the thing that
matters, a list of separate branches plus the arguments where the function
stops. Each branch is its own `polyline`, so the discontinuity survives from
the model into the DOM rather than depending on the renderer's good manners.

After the fix: **18 SVGs, 4 named.** Drawn piece counts confirm fidelity —
modulus 1 curve, **signum 3 branches**, **greatest-integer 7 steps**,
**reciprocal 2 branches with the excluded argument marked, not bridged**.

Defect classification: **product**, not harness and not content. No lesson
prose changed and no artifact version moved.
