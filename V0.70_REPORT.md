## The headline is not the redesign

v0.70 was commissioned as a visual release. The most important thing it found is
that **the product did not work**.

Walking the actual routes — which is what route-verified screenshots force you
to do — turned up four correctness defects that three releases of visual polish
had been sitting on top of. They are reported first because they matter more
than any of the design work.

### Defect 1 — four "Learn →" links did nothing at all

The Fractions chapter offered §7.2, §7.5, §7.6 and §7.8 as available. Tapping
any of them moved nothing. Two independent causes:

```js
onOpenSection={(sectionId) => {
  if (sectionId === 'ncert_gp_c6_s7_4') { setView('section74Practice'); }
}}
```

One hard-coded id — and it is §7.4, which is unpublished and therefore never
tappable, so the branch could not fire. **And** the outlet that actually renders
an open chapter was never passed `onOpenSection` at all, so the handler was
undefined there regardless.

Fixing only one would have left the links dead. Neither was visible to any test,
**because no test tapped** — every test asserted what the list *showed*.

### Defect 2 — four of five "Ready to learn" chapters were empty

Class 6 advertised 5 of 10 chapters as ready. Lines and Angles, Prime Time,
Perimeter and Area and Symmetry routed **zero** sections each. A student tapped
the card and found every one of the chapter's parts marked *Coming soon*.

`getStudentChapterAvailability` decided Learn by asking *"does any legacy module
mapped to this chapter have a lesson?"* — a question about Pragati's internal
inventory, not about the chapter a student taps. v0.64 had already fixed exactly
this for **Practice**; Learn was left deciding for itself and drifted.

**Class 6 now shows 1 ready chapter, not 5.** The number going down is the fix.

### Defect 3 — "Learn" overclaimed what the content is

The four Fractions parts that now route are backed by **legacy skill lessons**
(`FR.02`, `FR.03`, `FR.04`, `FR.05`), authored against the old 14-chapter book,
keyed by internal skill codes, never section-verified against Ganita Prakash,
never educator-reviewed.

Calling that "Learn" told a student Pragati teaches §7.2 of their textbook. It
now reads *"Related practice from an earlier Pragati topic — Practise →"*, and
`sectionRouting.ts` carries the provenance so the distinction is representable
rather than implied.

### Defect 4 — Home offered a chapter Learn said did not exist

After fixing Defect 2, Home still hero'd "Lines and Angles" because
`findContinueTarget` resolves through the legacy chapter model. Home and Learn
disagreed. Home now reads the same official availability everything else does.

Full detail in **`CLASS6_READY_TO_LEARN_AUDIT.md`**.

# A. Product

## 1. What actual screens were redesigned?

**Student Home** — the ~500px of empty grey is gone, filled with real data
rather than invented engagement. Hero action, then the open parts of that
chapter, then a horizontal chapter strip. No streak, no XP, no mastery ring.

**Class 6 Learn** — three visual registers instead of ten identical cards: one
featured chapter with hero artwork, a two-up grid of others that are ready, and
a quieter coming-soon group.

**Fractions chapter journey** — a connected path with stateful nodes
(open / started / practised / upcoming), where upcoming parts collapse to one
quiet line instead of occupying a card the size of an open one.

**Chapter motifs** elevated from 24px icons to tiles with textured accent fields
at a size where a compass and a factor tree are distinguishable.

## 2. Which old screens remain visually weak?

Stated plainly, because §33 asks for critical not promotional:

- **Teacher screens got the palette and nothing else.** §13 asked for a real
  redesign around teacher tasks. It did not happen — the release was consumed by
  the QA harness and four correctness defects. Teacher Overview is still a grid
  of "No completed sessions in this class yet" cards.
- **Admin and Teacher still look alike.** §14 is unmet.
- **1440 is still mobile-width content centred in a wide viewport.** §15 is unmet.
- **The first-run screen before a student record exists** is still the older
  three-card layout.

## 3–4. Did first-run and returning Home change materially?

Yes, and they are now genuinely different states derived from **recorded
sessions**, not assumed. First run gets orientation copy explaining that Pragati
follows the textbook; a returning student gets activity counts and section dots.
A student with no history can never see "Continue" — asserted by test.

## 5. Did Class 6 Learn move beyond repeated cards?

Yes — but note the irony: after the §27 truthfulness fix only **one** chapter is
available, so the "Also ready" register is currently empty. The layout supports
three registers; the content currently fills two.

## 6. Does Fractions have a more compelling journey?

Yes. Stateful nodes, a real rail, differentiated open/upcoming treatment. And it
now *works* — tapping a part opens something, which it did not before.

## 7. Did lessons actually render and get reviewed?

**Yes, and this is the first release where that is true.** The §7.4 lesson
renders with stacked fractions, numbered steps with separate reasoning lines,
green terminal ANSWER bands, and number-line visuals under "See it" labels.

Its captures are filed as `admin_*`, not `student_*`, because §7.4 is
unpublished and reachable only through the reviewer preview. Filing it as a
student capture would repeat exactly the mislabelling this release exists to fix.

## 8. Did Teacher get redesigned?

**No.** See §2. This is the largest unmet requirement in v0.70.

# B. QA

## 10. Which v0.69 screenshots were mislabelled?

`20-lesson-7_1-*.png` and `10-teacher-overview-*.png` — nine files across three
widths. Both are Student Home, and the two 390px files are **byte-identical to
each other**. The teacher one reads STUDENT MODE.

v0.69's report claimed lesson and teacher screens had been visually reviewed.
That claim was unfounded and should not have been written.

## 11. How does v0.70 prevent it?

`tools/routeContracts.mjs` declares, per route, text that **must** appear and
text that **must not**. A contract failure produces a failure, not a file. The
negatives do the work the positives cannot: a Student Home page *does* contain
the word "Teacher" (in its "Switch to teacher mode" button), so only
`mustNotContain: ['STUDENT MODE']` catches the defect.

The same contract objects are asserted by the unit suite, so harness and tests
cannot drift apart.

## 12. Did every required route assertion pass?

**Yes — 57 captured, 0 refused**, but only on the fifth run. The four refusing
runs are the evidence the guard works; each one found a real navigation fact:

| Run | Captured | Refused | Found |
|---|---|---|---|
| 1 | 18 | 39 | teacher mode never reached; `innerText` is CSS-uppercased |
| 2 | 18 | 39 | the mode toggle changes chrome but does not navigate |
| 3 | 45 | 12 | teacher sub-nav vanishes inside a sub-view |
| 4 | 51 | 6 | a lesson is an app-level view with no bottom nav |
| 5 | **57** | **0** | — |

Every one of those 39 first-run refusals would have shipped silently under
v0.69's harness.

# C. Curriculum

## 13–14. How many grades are verified?

**Still 5 of 12** (Classes 6, 9, 10, 11, 12). Seven need a human with a
textbook, and §26 is right that code cannot do it.

What changed is that the last mile now exists:

- **`generateRegistryPatch()`** turns a validated submission into a
  **deterministic TypeScript source file** ready to commit — chapters sorted, no
  timestamps, so two people entering the same book produce identical bytes and a
  real disagreement shows up as a diff.
- **Seven ready-to-fill templates** in `curriculum-verification/`, each carrying
  what to open and what to confirm on the imprint page.
- The Admin panel now shows the commit-ready file. It still does **not** save:
  a curriculum in localStorage cannot be diffed, checked against the book, or
  attributed, and would be the weakest link in a system built on auditable
  evidence.

The generated file carries a header requiring a **second reader** before merge.
Verification by one person is a claim; by two it is evidence.

## 15. What did the Class 6 Ready-to-Learn audit find?

Four of five chapters were false, four section links were dead, and the labels
overclaimed. Full detail in `CLASS6_READY_TO_LEARN_AUDIT.md`.

The finding worth repeating: **§7.4 is the only Fractions section with genuinely
authored official-section content — thirty-one worked examples, a frozen
artifact, three iterations of hand audit — and it is the one section a student
cannot reach.** Meanwhile the four they *could* reach are backed by grandfathered
material nobody has verified against the current textbook. That inversion is the
strongest argument yet for sending the §7.4 review.
