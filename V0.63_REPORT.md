## 1. Did the 5-vs-4 Fractions discrepancy get resolved?

**Yes — by removing the second decision-maker, not by changing a number.**

Root cause traced: §7.1's section record carries
`pragatiSkillIds: ['FR.02']` — a note that FR.02 is *related* — while
`itemAlignment` records FR.02 as exactly aligned to **§7.2**. The student
landing read `pragatiSkillIds.length > 0` and advertised "§7.1 Practice"
**backed by items authored for §7.2**. Listing is not alignment.

`eligibilityPolicy.ts` is now the single authority. Six surfaces call it
and none decides for itself:

Class 6 Learn · Fractions landing · Progress · Teacher coverage ·
Teacher Resources · Teacher assignment

There are no stored eligibility booleans; everything is derived, so the
answers cannot drift apart again. A test asserts the student count,
teacher coverage and alignment report all read **4**.

**Both numbers survive, separately reported.** `mapped = 5` (historical
topic overlap) and `practiceAvailable = 4` (material written for that
part of the book) are different true statements. The teacher UI explains
the gap in plain language rather than hiding it behind one figure.

## 2. What makes a chapter "Ready to learn" now?

An actual openable lesson — not a mapped module.

`getStudentChapterAvailability()` resolves the chapter's core modules,
expands them to skills, and requires at least one skill with a real
lesson. A chapter with items but no lesson reads "Practice", not "Ready
to learn".

**The grandfathering rule is now explicit and tested**
(`LEGACY_LESSON_GRANDFATHERING`): a legacy lesson is student-usable only
if the current textbook still places that topic at this grade. That is
why `fractions` and `geometry` remain visible while `decimals`,
`ratio_proportion` and `algebra` do not — the difference is *curriculum
placement*, not review status. Neither has been reviewed.

Grandfathering never applies to post-v0.61 content. §7.4 is the
highest-quality section in the product and stays invisible to students.

## 3. What makes a section "Practice" now?

All four required:

1. a skill **exactly aligned** to that section (`exact_section_candidate`);
2. that skill's module still Class 6 core;
3. real items behind it;
4. no reliance on a multi-section candidate.

FR.08 spans §7.6/§7.7/§7.8, so it makes none of them practisable.

## 6. Is student progress section-aware?

**Yes**, at the official-section grain, from real sessions only.

Sessions record `itemId`, so skills resolve through the item bank. A
session contributes to a section only when its skill is exactly aligned
and its module is Class 6 core. Consequences, each tested:

- **FR.08 contributes to nothing** — attributing a three-section skill to
  one section would invent a fact.
- **Displaced-module skills contribute to nothing.**
- **Legacy sessions are never re-labelled**; they keep their history and
  simply do not acquire a section they were never given.
  `unattributedSessionCount()` surfaces them rather than dropping them.

States are `not_started` / `in_progress` / `practice_completed` — facts
about activity. **There is no accuracy threshold anywhere in the file**,
deliberately: any threshold would be an uncalibrated mastery claim in
descriptive clothing.

practise grandfathered content, but a teacher setting it as official §7.x
work makes a curriculum claim, which requires educator-reviewed
alignment. Nothing is reviewed.

The panel shows the real reason per section and **no fabricated example
was inserted to populate a screenshot**.

## 9. How many sections are educator-reviewed?

**0 of 9.** Also 0 of 60 Class 6 sections.

## 10. Did any real reviewer response get ingested?

**No.** Both packages report `review_package_ready`, zero submissions.

`importReviewSubmission()` now validates package ID, reviewer identity
and role, ISO date, unknown item IDs, duplicate responses, decision
vocabulary, non-empty rationale, and repeat submissions — eight
rejection paths, each tested. Submissions are never mutated;
adjudication is stored separately.

**Semantic fix (§7):** answering 1 of 2 items and adjudicating it used to
report `review_adjudicated`. The release gate refused, but the *label*
read "done" — and labels get quoted in reports. New state
`review_partially_adjudicated` says what actually happened.
