## 3. Does the import reject a review for the wrong artifact?

**Yes** — five hard rejections, each tested: mismatched question-set
version, mismatched artifact ID, mismatched artifact version, stale
fingerprint, unknown item IDs. The fingerprint check compares against
the **current** content computed at import time, not a stored value, so
it cannot be satisfied by a stale copy of itself.

The fingerprint error names the consequence: *"The lesson changed after
this review was prepared; the affected items need re-review."*

## 4. What Package A decisions are required for §7.4 publication?

**Three: B1, C1, C2.** The Fractions section-coverage finding, and the
two competency mappings for this section.

Not required: A1–A5 (stage correction), B2–B5 (other chapters), C3–C5

## 5. What Package B decisions are required?

**Thirty of thirty-seven** — all M (mathematics), S (source fidelity),
A (age), V (visuals), X (misconceptions) and P (practice) items.

Excluded: T1–T4 (teacher notes) and O1–O3 (overall opinion). A reviewer
who declines to answer "would you use this with your own class" has not
withheld evidence about whether the mathematics is correct; requiring an
opinion would let a blank answer block a well-evidenced approval.

## 6. Can Package B alone publish it?

**No** — and this was the v0.64 defect.

`reviewDependencies.ts` declared that publication needs both packages.
The executable check asked
`mayAdvanceBeyondDraft(reviewRecordFor('B_demonstration'))` — Package B
only — and then consulted a hand-maintained `mappingReviewStatus` flag
that nothing kept in sync with the review record.

`mayPublishSection()` now enforces all four declared conditions.
`isSectionStudentReady()` delegates to it, so there is no second truth.
Tests prove Package B fully accepted alone cannot publish, and Package A
alone cannot either.

Two further guards: an **answered but unadjudicated** item does not
satisfy a gate, and an **adjudication without an answer** does not
either — an adjudication cannot stand in for a missing review.

## 7. Can unrelated Package A issues block instructional review?

**No.** `instructionalReviewIsBlocked()` returns false, and the required
subset excludes every unrelated item. §7.4 instructional review can
proceed today; only *publication* needs both packages.

## 8. What does `revise` mean operationally?

**It does not satisfy a gate.** Only `accept` does.

A reviewer saying "usable, but change this" has not approved what they
saw — they have stated a condition. The enforcement is structural rather
than procedural: a content-changing revision alters the fingerprint, so
the submission that prompted it no longer validates against the new
artifact and the affected items must be re-reviewed.

`content_revised` likewise does not satisfy a gate, for the same reason.

## 9. Does assignment identify a concrete artifact version?

**Yes.** For §7.4: `ncert_gp_c6_s7_4_lesson:practice:v1`, with a separate
`activityVersion` field. v0.64's `s7_4:practice` named a *slot*, so an
assignment made before a revision would silently point at content the
teacher never saw.

## 10. Is section lookup generic now?

**Yes.** `officialSectionById()` searches the whole verified registry.
`sectionEligibility()` previously looked records up via
`sectionsForChapter('ncert_gp_c6_ch07_fractions')` — a hidden Fractions
assumption that would have returned an honest-looking but meaningless
answer for any other chapter. Tested against a Fractions section, a Lines
& Angles section, an unmapped Chapter 1 section, and an unknown ID.

**This is not permission to author other chapters.** Fractions remains
the only pilot.

## 11. Is §7.4 still draft?

**Yes.** `authored_draft`, invisible to students, non-assignable,
`mayPublishSection` refuses.
