## A third instance of the scoping defect

v0.81 found the review system and the completeness assessor could each
see only one chapter. Authoring the interactive practice found a third:
`Choice.chapterMisconceptionId` was typed `FractionsMisconceptionId`, so
a Number Play item was **structurally incapable of carrying a
diagnosis** — a distractor could not name the error it detects.

Fixed as the design note in `misconceptionResolver.ts` always intended:
`MisconceptionRef` gains a per-chapter member rather than either enum
being widened, and `chapterRef()` decides the registry from the id
itself, so an item cannot attach a Number Play error and label it a
Fractions one. §7.4's payload is untouched — its choices never set the
key — and the fingerprint test proves it rather than the comment
asserting it.

## Completeness, honestly

| Section | v0.81 | v0.82 |
|---|---|---|
| 3.1 | incomplete — no visual, no interactive practice | **complete draft** (visual waived) |
| 3.2 | incomplete — no interactive practice | **complete draft** |
| 3.3 | incomplete — no interactive practice | **complete draft** |

**The format came from the mathematics, not the renderer.** §3.1 is
about choosing an interpretation, so multiple choice with the
interpretations students actually make. §3.3 is about reading distance
on a line, so two items use the real `select_point_on_number_line`
format and are judged exactly.

**§3.1's visual is waived, not faked.** A drawing here would be twelve
stick figures for "12 students" — illustrating the sentence without
teaching the idea — or a bar chart, which imports comparison machinery
the section deliberately does not use yet. The waiver is recorded with
that argument and is a judgement a reviewer may overturn. Interaction
was *not* waived; it was authored.

**Diagnosis stays conservative.** A distractor carries
`chapterMisconceptionId` only where no other route produces it — "45"
for 5, 10, 20, 40 is adding the first step and nothing else. Everything
else gets neutral corrective guidance.

## What is specified and deliberately not built

The right interaction for §3.2 is selecting cells in a live grid, judged
as a **set** against `supercellsFor()`. That needs a
`select_cells_in_grid` format, a judge and a selection affordance in the
renderer. Recorded as a requirement in
`numberPlayPracticeItems.ts`, for the same reason `PlaceValueSpec` was
specified and not built in v0.81: the multiple-choice items teach the
definition correctly today, and a broken selection surface would teach
it worse.
