## 6. Which sections are educator-reviewed

**None.** Both review packages report `review_package_ready` with zero
submissions.

`educatorReview.ts` keeps three states distinct — `review_package_ready`,
`review_received`, `review_adjudicated` — computed from what exists, with
no assignable state field. A received response is **not** an adjudication
and does not unlock release; a test proves it. Any single
`content_rejected` or `more_evidence_required` blocks the whole package:
content is not shipped on a majority vote.

## 7. Interactions beyond MCQ

Section 7.4 practice, 6 items:

| Format | Count |
| :-- | --: |
| `select_point_on_number_line` | 3 |
| `numeric_entry` | 1 |
| `fraction_strip_selection` | 1 |
| `multiple_choice` | 1 |

All judging is **exact integer arithmetic**. `tickValue()` derives a
tick's value by cross-multiplication — placing 5/4 on a 0–2 line yields
10/8, exactly equal to 5/4, with no float produced. A test asserts
666/1000 is rejected as an answer of 2/3; a float comparison with a
tolerance would accept it.

Accessibility: real focusable `role="radio"` elements, so arrow keys and
screen readers work without a parallel implementation. 44 px hit areas
regardless of drawn tick spacing.

**Feedback maps only where the format can support it.** One tick short
IS the counting-ticks error and nothing else, so it names it. Any other
miss gets neutral corrective guidance rather than a guess about intent.
Verified in the captures.

**A design tension I resolved by judgement.** §9 required a working
number-line interaction for §7.4; §12 required draft content to stay
away from students. §7.4 is draft. I placed the working interactions in
the **reviewer preview** — a reviewer cannot judge an interaction from a
description, and this is where the review happens. It becomes
student-reachable when the section passes review. You may disagree with
that reading.
