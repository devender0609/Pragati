## B/C. The defect, and why the values were not patched

SEQ-06 reused the limit table, which samples a real variable from **both
sides** of its target. A sequence of partial sums has no left side: S_n
exists at n = 1, 2, 3 and nowhere else. The rendered table therefore opened
with six `no value` cells before the first real number.

**Classification: product.** The model was right and the data was right; the
figure was the wrong semantic shape.

Patching the cells — hiding the left half, blanking them, inventing values
at n ≤ 0 — would have left a two-sided representation pretending to be
one-sided. The representation contract was replaced instead.

## D/E/F/G/H. The forward-indexed figure

`IndexedSequenceSpec` walks forward from the first index. Rows carry n and
the value; the limiting value sits **below the table**, because it is not a
term of the sequence.

- **First row is n = 1** with a real value, and the validator rejects any
  figure starting elsewhere or running out of order
- **Every value comes from `partialSums`**, and
  `partialSumFigureMatchesModel` rejects drift — a tampered row 3 reports
  *shows 9 but the model gives 1.75*
- **The limit comes from the convergence result**, never authored beside it
- **A divergent figure carries no target**, only the model's named reason.
  `V_DIVERGENT_SUMS` has no `approaches` field and contains no Infinity or
  NaN anywhere in it
- A figure claiming **both** a limit and a reason is rejected

This is not a second convergence engine. The figure reports what the model
concluded; it decides nothing.
