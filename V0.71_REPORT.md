# v0.71.1 — the deferred requirements, completed

## §12 — the lesson is staged

The v0.70 route-verified capture measured the problem exactly: **8,703px of
continuous page at 390px**. Explanation, two visuals, five worked examples,
common mistakes, guided practice, independent practice, reasoning and summary,
all rendered at once.

Five stages, following the pedagogy rather than the data model:

**Learn the idea → See it → Worked examples → Try it → Think deeper**

The same §7.4 lesson now opens at 4,401px, and the examples stage is a separate
screen. **Four taps cross the whole lesson** — a test asserts ≤4, because §12's
explicit warning is "do NOT require 25 taps".

Every stage stays reachable from the stage bar at any moment. That is
deliberate: a lesson is a reference as much as a path, and locking a student out
of the worked examples while they attempt practice would be the gamified reading
of this change and the wrong one. The single long page technically allowed
going back and practically did not, because the thing they wanted was 4,000px
away.

## §13 — worked examples show mathematical structure

The v0.70 version numbered its steps. It still rendered each step as two
paragraphs of equal weight, so the structure of the mathematics was carried
entirely by font weight.

Now explicit and consistent:

| | |
|---|---|
| **PROBLEM** | the question, on its own tinted surface |
| **STEP n** | the move, the largest type in the card, on a connected chain |
| **WHY** | the justification, visibly subordinate — indented, smaller, rule-marked |
| **ANSWER** | a terminal band that cannot be mistaken for a step |

Progressive disclosure is kept: a student who can see step 3 before attempting
step 2 will read step 3. A test asserts the answer is absent until the steps
have been walked.

## §14 — the pedagogy audit, deferred twice, now done

`pedagogyAudit.ts`. Nine findings across the five things §14 asks about.

| Disposition | Count |
|---|---|
| Addressed by presentation | 3 |
| Recorded for review | 3 |
| Considered and kept | 3 |

**Addressed by moving existing material, not by writing more:**

- Every section rendered as one page with no boundary between "being told" and
  "having a go" → the staging above.
- **The common-mistakes list sat after all worked examples and before practice
  — the one position where it helps least.** Too late to shape how a student
  reads the examples, too early to answer a mistake they have actually made. It
  now sits on "Learn the idea", beside the idea the mistakes are about.

**Recorded, not acted on**, because acting means authoring:

- §7.6 carries the equivalence argument in two long prose paragraphs and has no
  visual showing the *cut* happening — the chapter's strongest prose-to-visual
  candidate.
- §7.9 has five paragraphs and zero visuals, the only section with none.
- §7.8's unlike-denominator examples do two jobs at once (find a common
  denominator, then add); a student who fails cannot tell which half.

**Considered and kept**, with reasons: §7.4 is the frozen review anchor and must
not move; §7.9's light practice was argued in v0.68 §5; and the nine neutral
distractors are *correct* under v0.70 §24, not a defect.

§14 says "do not add volume", and the temptation in a pedagogy audit is always
to write another example. **No content was added.** The audit record states in
its own disclaimer that it is a self-audit by the same process that authored the
content, and is not educator review.

## §18 — Admin now looks like Admin

A dark slate banner stating its scope, and an explicit note that this surface

## QA — 63 captured, 0 refused

Contracts added for each lesson stage. **The run found a defect in the harness
itself that had been passing since v0.70:**

`admin_feedback_incorrect` looked for `[role="radio"]` — a selector only the
area-model format uses, **and §7.4 has no area-model item, so nothing was ever
clicked**. The contract required the lowercase word "answer", which some
unrelated block on the then-single-page lesson happened to supply. The capture
passed for four widths across two releases without ever exercising the thing it
claimed to show. Staging the lesson is what exposed it.

It now clicks one known distractor by text — §7.4's *"It cannot be shown,
because 1/4 is less than 1"* — which states its own reasoning and therefore
deterministically produces the **diagnosed** feedback heading rather than the
neutral one. Two intermediate versions of the fix also failed, both because
"whatever the first radiogroup offers" depends on render order across six
groups of four formats.

# A. Student

## 1. Is first-run Home part of the same product as returning Home?

Yes. Both now read the official curriculum through `class6ChapterCards()`, both
open a chapter through the same official route, and both use the same visual
system. First run gets orientation; returning gets continuation. The two
generations of Pragati that used to sit either side of a single session boundary
are gone.

## 2. Can zero history still produce a weakness claim?

**No.** The v0.70 screen said *"Practise a weak skill"* and, with zero recorded
sessions, *"No sessions yet, so we picked FR.02 as a sensible starting point."*
There is no evidence any skill is weak. That is the assessment equivalent of
fabricated progress.

The fallback is deleted, not hidden: `computeSkillProgress` is no longer
imported by this screen at all. The first action now comes from the
**curriculum**, which is true on day one and needs no history. A test asserts the
word "weak" appears nowhere.

## 3. Are internal skill IDs gone?

Yes from every student surface. A test scans the rendered first-run screen for
`FR.\d\d`, `GB.\d\d`, `DE.\d\d`, `RP.\d\d`, `AL.\d\d` and `mixed_fractions`.
Legacy practice activities now carry plain names — *"Fractions as parts of a
whole"*, *"Mixed fractions"* — and the codes remain valid in Admin, logs and
research metadata.

## 4. Is learning the primary first-run action?

Yes. *"Start recommended assessment"* no longer leads. The order is: start
learning → explore your chapters → try a set of questions. Assessment
infrastructure is untouched; only its priority changed. A test asserts
"learning" appears before "questions" in the rendered text.

## 5. Is Progress Start/Continue correct?

Yes, and this was **two** defects. The screen said *"0 of 9 parts started"*,
every row read *"Not started"*, and the button said *"Continue: 7.1 …"* — and
§7.1 is not openable, so the button also led nowhere.

`continueFrom` returns the next section in official order regardless of whether
Pragati can open it. Correct for a different question. The CTA now picks from
sections that actually route: **Continue** where there is unfinished work,
**Start** otherwise, and **no button at all** when nothing routes.

## 6. Are official learning and legacy related practice visibly separated?

Yes, and this was the most consequential change of the release.

v0.70 rendered four of the nine official parts as tappable "Practise →" rows,
because legacy skill lessons happened to map to them. That put related practice
**inside the official chapter sequence** — which is exactly what makes a student
believe Pragati teaches §7.2 of Ganita Prakash. It does not.

The journey now shows the textbook sequence, all nine parts, all Coming soon.
Below it, a separate section:

> **Practice you can do now**
> These are extra practice activities on fractions. They are not the chapter
> lessons above — those are still being written.

Also fixed under §8: the hero's filled/unfilled dots showed **availability**
using the universal convention for **completion**. A student reading "●●○○○"
beside "9 parts" reads progress. It now says so in words: *"9 parts in this
chapter. 4 related practice activities are available now."*

## 7–8. Is the lesson still a giant document?

**Superseded by v0.71.1 — see the section above.** As shipped in v0.71.0 the
answer was yes, and §12, §13 and §14 were unmet. All three are now done: the
lesson is five stages, worked examples have an explicit mathematical hierarchy,
and the pedagogy audit is recorded in `pedagogyAudit.ts`.

## 9. What remains visually weak?

- **The lesson**, as above.
- **Learn at 1440** is still a centred column; only Home got a composed
  two-column layout.
- **Admin** remains dense in a way that is appropriate but undifferentiated.

# B. Teacher

## 10. Was Teacher actually redesigned?

Yes — the Overview, which was the specific failure. It was five cards, and with
a fresh class every one was a negative: *No completed sessions*, *No active
assignment*, *Not enough recent activity*, twice more. A teacher was told five
times that there was nothing, and offered nothing to do about it.

**Emptiness is not a finding.** It is a state with obvious next steps.

## 11. What does empty-state Teacher help a teacher DO?

Three numbered steps: set up a class, see what is available (*"1 of 10 Class 6
chapters have activity a student can open today"* — real, and the honest
number), assign something. Each with one button.

When evidence exists the same screen leads with the evidence, and the
attention card appears **only when someone is flagged** — v0.70 rendered
"Nobody on the flag list right now" as though the absence of a finding were
itself a finding.

## 12. Was mobile navigation simplified?

Yes: six tabs to **four** on mobile (Overview, Classes, Assign, Resources).
Desktop keeps all six. At 390px six labels get ~62px each, and "Assess" and
"Insights" shared an icon, so two of the six were visually identical. Nothing
was removed — both remain reachable from the desktop header and from Overview.

## 13. Are Teacher and Admin visually distinct?

**Partially, and I am not claiming more.** Teacher lost its prototype chrome and
gained an action-led empty state, which separates them in tone. Admin was not
redesigned. §18 is not fully met.

## 14. What remains prototype-quality on Teacher?

Classes, Assign, Insights and Resources received the palette and the nav change
only. Insights in particular is still a dense internal readout.

## §16 — prototype language

*"Teacher · Mathematics · Prototype"* is gone from the workspace chrome. The
footer read *"Pragati prototype · Pre-pilot content · Not a calibrated
assessment…"*; it now states the substantive limitation — no calibrated score,
teacher judgement needed, calibration study before operational use — without the
running commentary on the software's maturity. **The claim is unchanged**; a
test asserts it, and asserts the calibration-study requirement specifically.
