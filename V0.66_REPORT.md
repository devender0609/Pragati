## 1. Was the circular publication gate fixed?

**Yes.** `mayPublishSection()` used `isStudentLearningReady()` as its
readiness precondition — a function requiring every student-facing axis
to already read `published`. The gate asked *"is this already
published?"* before permitting publication. Nothing could ever pass it;
the only reason it went unnoticed is that the review gates fail first.

`isReadyForStudentPublication()` now requires the axes one step **below**
published: `educator_reviewed` on the lesson, `reviewed` on worked
examples, `mathematically_reviewed` on visuals, `reviewed` on both
practice axes.

Tested directly: a fully reviewed, unpublished draft returns
`isReadyForStudentPublication = true` and `isStudentLearningReady =
false`.

## 2. Publication-eligible vs published

| | |
| :-- | :-- |
| **Eligible** | Every gate passes; the transition *may* happen |
| **Published** | The transition *has* happened; content may be served |

Passing review does not publish anything. Eligibility is derived;
publication is a recorded historical fact.

## 3. What explicit action publishes a reviewed artifact?

`publishSectionArtifact()` — the only route. It refuses unless
`mayPublishSection()` succeeds, and the caller cannot assert its own
fingerprint or version: both are read from current content, so a stale
artifact cannot be published by claiming it is fine.

It writes a receipt: section, artifact ID and version, fingerprint at
the moment of publication, review-build ID, date, publisher, and **the
adjudications that authorised it** by package and item.

Refusals tested: gates unmet · stale fingerprint · wrong version ·
arbitrary section ID · already published.

**The register is empty. Nothing has been published.**

| :-- | :-- |

## §6 SHA-256 decision

**FNV-1a retained.** Reasons, recorded so the choice can be revisited:
the threat is accidental drift rather than forgery; the only synchronous
SHA-256 available is `node:crypto`, which would break the browser build
this module is imported into; `crypto.subtle` is async and would make
every caller async for no evidential gain.

Consequences stated rather than glossed: this is **not** cryptographic,
no document calls the review "cryptographically tied", the full 8-hex
fingerprint is authoritative, and the short code is a convenience for
quoting in email. The canonical payload is separated so the hash
function can be swapped without touching anything else.
