## §1-§2 — the stale waiver

`instructionalCompleteness.ts` still carried the §3.1 visual waiver
written for the **rejected v0.79 reading** — "a visual would be
decorative" — while the rewritten §3.1 teaches adjacent taller
neighbours and carries two semantic NumberGrid visuals.

Removed, with no replacement. A waiver that outlives the argument for it
is worse than none, because it keeps asserting a judgement nobody holds.
§3.1's visual requirement is now **required and satisfied**.

The test asserting the opposite had passed for two releases. Replaced —
a test that still passes is not the same as a test that still says
something true.

## §3-§7 — the last Fractions-only consumers

| File | Was | Now |
|---|---|---|
| `coverageWording.ts` | `recordStateCounts()` saw Chapter 7 only | all authored sections, readiness by chapter |
| `stateDocs.ts` | deprecated Fractions summary | chapter-scoped |
| `productionBrief.ts` | Fractions-only authored lookup | cross-chapter |

The effect is visible in the counts: **80 → 77** sections holding no
instructional content, because Chapter 3's three stopped being counted
as bare structure.

**Left Fractions-specific on purpose:** tests and tallies genuinely about
Chapter 7. Two assertions I first "corrected" to 12 were reverted to 9 —
a Chapter 7 figure should read 9, and changing it would have erased the
distinction this work exists to draw.

## §8 — alignment gates packaging, not just readiness

`sectionsNeedingPackages()` gated on structural completeness alone. A
complete-but-misaligned section could have been packaged and sent, which
wastes the scarcest thing in this project: an educator's afternoon.

Packaging now uses the same source-alignment gate as readiness, failing
closed on a missing record. Fractions keeps the chapter-wide legacy
exemption already documented in readiness.

## §9-§13 — the packages themselves

**Chapter 3 packages exist**, in their own folder:

`PRAGATI_CHAPTER_3_REVIEW_PACKAGES/`
- `SECTION_3_1_FOR_REVIEWER.md` — artifact **v2**
- `SECTION_3_2_FOR_REVIEWER.md` — artifact v1
- `SECTION_3_3_FOR_REVIEWER.md` — artifact **v2**
- `index.json` — codes, artifact versions, fingerprints

Fractions' folder is untouched and §7.4 is never regenerated.

**Chapter prose is generated, not hard-coded.** It said "one section of a
Class 6 fractions chapter" for every package — simply false on a Number
Play one.

**The Fractions-only review note is gone from Chapter 3.** The
shaded-pieces paraphrase obligation belongs to v0.77.2 Fractions
lessons; asking a Number Play reviewer about it would send them looking
for text that does not exist. Each Chapter 3 package instead names its
own enrichment: §3.1's plants and the stated tallest-reports-0 rule,
§3.2's tie case, §3.3's original windows and named method.

**"You are the first reviewer" no longer special-cases §7.1.**

**Artifact versions are section-correct.** One package-wide constant
reported version 1 for everything, so a reviewer handed the rewritten
§3.1 would have been told they were reading the draft it replaced. §14's
distinction is documented in code: the **question-set version** versions
the instrument, `contentArtifactVersion` versions the lesson.

## §15 — review_ready now means a file exists

Package emission runs through the test harness, so the same run that
claims readiness writes the artifact, and a later run verifies what is
on disk. The system cannot report "blocked on a person" while no
reviewer-facing file exists.
