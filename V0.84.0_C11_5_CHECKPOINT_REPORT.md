## C. Chapter 10 — conic forms verified on the page

**Parabola: `y² = 4ax`**, with Definition 3 for the latus rectum
(perpendicular to the axis, through the focus, endpoints on the parabola),
`AC = FM = 2a`, length `= 4a`.

**Ellipse: both orientations.** `x²/a² + y²/b² = 1` and `x²/b² + y²/a² = 1`,
with foci `F₁(−c,0)`, `F₂(c,0)` and vertices `(0,±a)`, `(±b,0)`.

This is the case the prompt warned about, and it resolves the other way: the
apparently swapped denominator is **a genuine second standard form for the
major axis along y**, not a defect. Had I only extracted text I would have
seen two contradictory equations for one object and been unable to tell which
was wrong. Both are recorded as distinct forms.

= 247` — a nested fraction that flattens unrecognisably.

# Addendum — build-configuration repair (package `-b`)

The checkpoint-76 package failed to deploy twice with:

```
src/curriculum/__tests__/v070Routes.test.ts(12,8): error TS2307:
  Cannot find module '../../../tools/routeContracts.mjs'
```

Diagnosis: the source is sound — `npm ci && npm run build` passes here, and
both `tools/routeContracts.mjs` and its `.d.mts` declaration are in the
package. They are not reaching the git repository, so a **dev-only test
fixture was failing a production deployment.**

Two separate problems, fixed separately.

**The build should not have cared.** `tsconfig.json` includes `src` and
`tools` so unit tests can assert against the same route contracts the
screenshot harness uses. That is correct for CI and wrong for deployment:
nothing under `__tests__` or `tools` is bundled by Vite, yet either could stop
a deploy. Added `tsconfig.build.json`, extending the strict config and
excluding tests and tools; `npm run build` now uses it, while `npm run
typecheck` keeps the full strict config. **No checking is lost** — the two
paths cover different scopes on purpose.

Verified against the actual failure: with `routeContracts.mjs` and
`routeContracts.d.mts` deleted, `npm run build` **succeeds**; with them
restored, the full `tsc --noEmit` passes. Full suite **2530 tests / 124
files**, curriculum validation, and both public-safe and preview builds pass.

**The files should still be in the repository.** The build change stops this
class of failure; it does not explain the absence. Worth running once:

```
git ls-files tools/
git check-ignore -v tools/routeContracts.mjs
git config --get core.excludesfile
```

A global excludes file is the most likely culprit, since `.mjs` tooling is
commonly ignored and the package itself ships no `.gitignore`. Until that is
found, every new checkpoint package will drop the same two files — and
`git push --force` will keep making the remote match.

No curriculum, lesson, source-model or review artifact changed. Class 11
source remains frozen; the verdict above stands.
