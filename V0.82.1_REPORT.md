## §A — the false diagnosis is gone

Item `s33.p3` attached its "1000" distractor to
`assumes_ticks_step_by_one`, which means the student believes
consecutive ticks differ by **1**. Choosing 1000 shows nothing of the
kind — the code comment beside it even described a different error.

Two reasoning paths reach 1000: reaching for a familiar round thousand,
or dividing 2000 by 2 instead of by 8. A response admitting more than
one reading is not evidence for either, so the attachment is **removed**
and the item gives neutral corrective feedback.

**No replacement misconception was invented** to keep the label. That
would be manufacturing a record to justify a diagnosis.

Remaining §3.3 diagnosable distractors: `assumes_line_starts_at_zero`
only, on the item that asks directly whether every number line starts at
zero — where the wrong answer *states* the belief rather than hinting at
it.

## §B — tick language

"The third tick from the left" is ambiguous when the endpoint is itself
a tick. All ordinal phrasing in §3.3 is now interval-relative: "three
intervals to the right of 86,000", "seven intervals along from 15,070".
The mathematical values never changed; only the wording did.

## §E — the misconception contract, decided

**Option A.** `misconceptionRef` is the modern mechanism — a reference
naming its registry. `chapterMisconceptionId` is marked
`@deprecated` as a legacy compatibility field, documented with why it
exists (§7.4's frozen payload predates the reference) and what to use
instead.

One real bug fell out: `isChapterMisconceptionId` narrowed to
`FractionsMisconceptionId` while its registry already held Number Play
ids — so it returned true for a Number Play id and told the compiler it
was a Fractions one. A lie the type system could not catch. It now
narrows to the union it actually tests.
