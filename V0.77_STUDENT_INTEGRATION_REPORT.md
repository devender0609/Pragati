compositions were replaced in place, not switched away from. The

## Two defects the production captures caught that the unit tests did not

**The audience inference was wrong.** I first derived "is this a
student" from whether `studentId` was passed. The unit test passed and
the capture harness refused 25 screenshots: App's legacy
`view === 'learn'` route renders the lesson for a student *without* a
studentId, so "FR.02" and "Reteach:" were on a real student screen.
Audience is now an explicit prop defaulting to `student`, so a new call
site must *ask* for internal identifiers rather than leak them by
forgetting.

**Item ids survived in Try-it.** "Q1 · FR.02-01 · diff. 1". Students now
see "Question 1 of 5".

Both were found only because each capture asserts a forbidden stale
marker as well as a required one.

## Tests changed rather than product

Two, both documented in place:

- `v063PilotLoop` asserted `buttons.length === 1` on Learn as a proxy for
  "no unavailable chapter is tappable". Learn now legitimately offers
  four practice activities. The proxy was replaced with the invariant
  itself: no button contains an unavailable chapter's title.
- `lessonInShell` asserted "FR.02" was on screen as cheap proof the
  lesson body had rendered. It now asserts the lesson's actual content.
