## 3. Pipeline integration — the central fix

`prepareGrowthAdministration.ts` is now the only path to a formal form.

**What was wrong:** v0.56 had two paths. The tested one ran items
through `evaluateGrowthItemEligibility()` and the `AssessmentAssembler`.
The one the product used was `buildGrowthPool()` — checked `use`,
checked a specification ID existed, checked a count, returned
`secure.slice(0, n)`.

**So every safeguard the suite proved applied to a code path no teacher
could reach.** A `growth_field_test` item with a *draft* specification,
no expert review and no accessibility review would have passed the
production check and failed the tested one.

The pipeline runs: context support → item eligibility → metadata
completeness → blueprint assembly. Eligibility runs **before** assembly,
so an ineligible item can never help satisfy a domain minimum.
`buildGrowthPool()` is no longer called by any product code.

## 6. Scoped, coverage-driven readiness

`evaluateScopedGrowthReadiness()` takes a scope (module, official
chapter, required competencies, framework version) and evidence keyed
**by competency**.

- One advancing strand no longer advances unrelated chapters — tested
  with Fractions advancing while Geometry stays `not_eligible`.
- Blockers name the competency: *"No item specification covers
  RAT.COMPARE"*, not a count.
- A test asserts 99 specifications on one competency does **not** make
  the scope ready — the v0.56 `specificationCount > 0` rule would have
  passed it.
- No arbitrary minimum item count was invented; the only counts used
  come from the versioned administration specification via the
  assembler.

## 7. Accessibility model unified

The duplicate four-value `Accommodation` enum is deprecated (retained
so stored sessions load). Teacher Assess now renders the canonical
categorised supports, each showing whether it is universal, expected
not to change what is measured, or may change it.

The blanket claim *"an accommodated sitting may not be directly
comparable"* is **gone** — verified as absent across all 12 screenshots.
`SessionSupportRecord` captures support ID, category, comparability *at
administration time*, and specification version, because a
classification may change later and a past session must remain
interpretable under the rules that applied then.

## 8. Structured source inspection

`SourceInspectionRecord` replaces `inspected: boolean`. A record counts
only when it has a complete status, a named inspector, a valid date,
recorded pages/sections, evidence records created, and an official URL.

**Tested: setting `inspected: true` on every required source does NOT
open the gate** — the gate derives inspection from records and ignores
the boolean. Two records exist (both CBSE documents genuinely read);
PARAKH, NCF-SE and Ganita Prakash correctly report as uninspected.
