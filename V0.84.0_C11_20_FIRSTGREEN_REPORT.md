`catalogue.prerequisiteLessons` now renders as its own group, headed **"Before
you continue"**, placed **above** the textbook chapters because a prerequisite
read after the unit needing it is no prerequisite.

It is not a chapter. It reuses the existing lesson-row contract — same
`contentArtifactId`, same `data-artifact-id` hook, a new `onOpenLesson` prop
on the chapter screen — so there is no second routing mechanism. The row is
labelled "Prerequisite", with no internal status jargon on the student
surface.

## Product presence is not data presence

This failure class has now appeared four times: `VennSpec`, the function
graphs, `ProofLayoutSpec`, and these catalogue rows. The standing rule: any
new first-class collection on a product surface needs a data test, a
renderer-presence test, and a browser path test. Two of the three are not
enough, and this checkpoint is the proof.
